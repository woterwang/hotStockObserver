针对 `volume-surge`（强势资金突破）策略的优化方案：

### 优化方案：基于“板块共振”与“龙头效应”的策略升级

#### 1. 核心思路

目前的 `volume-surge` 策略主要基于个股的**量价行为**（涨幅、成交额、量比等）进行筛选。虽然能选出强势股，但缺乏对**市场主线**的感知。

**优化核心**：将“个股单打独斗”升级为“板块共振”。
- **板块共振**：个股放量上涨时，如果其所属板块也是当日热点，则上涨持续性更强。
- **龙头效应**：识别个股在板块中的地位，优先选择板块龙头或前排个股。

#### 2. 具体优化步骤

我们将利用新增的三个接口，在原有的评分体系中加入“概念热度”和“板块地位”两个新维度。

##### 第一步：获取市场风向（前置准备）

在执行选股逻辑之前，先获取当日的市场热点数据。

*   **调用接口**：`thsConceptHotRankService.fetchHotRank('concept')`
*   **目的**：获取当日实时热度最高的前 20-50 个概念板块。
*   **数据处理**：建立一个 `HotConceptMap`，存储板块名称及其热度排名（排名越靠前，权重越高）。

##### 第二步：个股深度扫描（增强分析）

在 `fetchFromWencai` 初步筛选出股票（例如前 50-100 只）后，对这些候选股进行深度扫描。

*   **调用接口**：`thsStockConceptService.fetchConcepts(code)`
*   **目的**：获取个股详细的概念信息，特别是它属于哪些板块，以及它是否是这些板块的龙头。
*   **逻辑**：
    1.  **热点命中检查**：遍历个股所属的所有概念，检查是否命中 `HotConceptMap` 中的热门板块。
    2.  **龙头身份确认**：检查返回数据中的 `leading` 字段，判断该股是否被标记为某板块的龙头。

##### 第三步：评分模型升级（加权算法）

在原有的评分（Score）基础上，增加以下加分项：

1.  **热点板块加分**：
    *   如果个股属于 Top 5 热门板块：+20分
    *   如果个股属于 Top 6-10 热门板块：+10分
    *   如果个股属于 Top 11-20 热门板块：+5分
    *   *注：如果命中多个热点，可叠加，但设置上限。*

2.  **龙头身份加分**：
    *   如果个股是任意热门板块的“龙头”（在 `leading` 列表中）：+30分
    *   如果个股是任意热门板块的“成分股”（在 `components` 列表中）：+10分

3.  **板块效应加分**：
    *   利用 `concepts/detail` 返回的 `riseCount`（上涨家数）和 `limitUpCount`（涨停家数），计算板块情绪。
    *   如果所属主板块涨停家数 > 5：+10分（说明板块效应强，容错率高）。

#### 3. 代码实现思路 (伪代码)

建议修改 volumeSurgeService.ts，在 `getVolumeSurgeStocks` 方法中注入优化逻辑。

```typescript
// 1. 获取市场热点
const hotRankResult = await thsConceptHotRankService.fetchConceptHotRank();// 目前接口最多只返回20个热点
const hotConcepts = hotRankResult.items.slice(0, 20); // 保险取前20个热点
const hotConceptNames = new Set(hotConcepts.map(c => c.name));

// 2. 初筛股票 (保持原有逻辑)
let candidates = await this.fetchFromWencai(dateStr);

// 3. 深度扫描与加权 (新增逻辑)
// 为了性能，建议只对初筛评分前 50 的股票进行深度扫描
const topCandidates = candidates.sort((a, b) => b.score - a.score).slice(0, 50);

for (const stock of topCandidates) {
  try {
    // 调用新接口获取详情
    const conceptDetail = await thsStockConceptService.fetchConcepts(stock.code);
    
    let conceptScore = 0;
    let hitHotConcepts = [];
    let isLeader = false;

    // 遍历个股所属概念
    for (const c of conceptDetail.concepts) {
      // A. 检查是否命中热点
      if (hotConceptNames.has(c.name)) {
        conceptScore += 10; // 基础热点分
        hitHotConcepts.push(c.name);
        
        // 额外：如果是前5热点，额外加分
        const rank = hotConcepts.findIndex(h => h.name === c.name);
        if (rank < 5) conceptScore += 10;
      }

      // B. 检查是否为龙头 (检查 leading 列表)
      // 注意：leading 里的 code 是同花顺格式，可能需要处理
      const isLeading = c.leading.some(l => l.code === stock.code);
      if (isLeading) {
        conceptScore += 20; // 龙头大加分
        isLeader = true;
      }
    }

    // 更新股票总分和信息
    stock.score += conceptScore;
    stock.hotConcepts = hitHotConcepts; // 记录命中的热点，用于前端展示
    stock.isLeader = isLeader;          // 记录龙头身份
    
  } catch (e) {
    // 容错处理，避免个别接口失败影响整体
    logger.warn(`获取个股概念失败: ${stock.code}`);
  }
}

// 4. 重新排序并返回
return topCandidates.sort((a, b) => b.score - a.score);
```

#### 4. 预期效果

*   **过滤杂毛**：原本可能选出一些虽然放量但属于冷门板块的“一日游”股票，优化后这些股票排名会下降。
*   **锁定龙头**：处于热点板块且被标识为龙头的股票，排名将大幅提升，更容易被策略捕获。
*   **增强解释性**：选股结果将包含“所属热点”和“龙头标识”，让使用者一眼看出上涨逻辑。


#### 5. 进一步建议

你的方案方向是对的（“量价强势 + 题材共振 + 龙头优先”）。从更专业/更可回测的角度，我建议把三类概念数据拆成“风向、强度、个股地位”三层，并把打分从“简单叠加”升级为“主概念驱动 + 上限约束 + 缺失降级”。

**1) 框架建议（把 3 个接口分工明确）**
- **实时热度** `GET /api/market/concepts/hot`：回答“今天资金在聊什么”（情绪/关注度），适合做**风向过滤/加权**。
- **当日强度** `GET /api/market/concepts/rank?date=...`：回答“今天板块涨得是否真强”（强度/成交/速度等），适合做**确认信号**，避免纯热度噪音。
- **个股概念详情** `GET /api/stocks/:code/concepts/detail`：回答“这只票在该题材里是什么位置”（leading/components、板块涨停家数等），适合做**地位加权 + 解释字段**。

**2) 评分模型建议（可直接落地为规则）**
- 总分用线性融合而不是全靠加分：  
  $$Score = Score_{volume} + \beta \cdot Score_{concept}$$  
  建议起步 $\beta \in [0.2,0.5]$，先别让题材把量价主信号“盖住”。
- **主概念选择（关键）**：不要把命中的热点概念全加起来，容易“多概念票”虚高；建议：
  - 以 `concepts/detail` 返回的概念列表中，满足“热度/强度门槛”的概念里，取 **Top1~Top2** 作为“主概念”，其余只做小幅加成或不计。
- **概念分拆三部分**（并各自设置上限）：
  - **热度分（风向）**：按 `concepts/hot` 的 rank 做衰减（而不是档位跳变），例如  
    $$S_{hot} = \min(20,\; a \cdot (K-rank+1))$$  
    其中 $K=20$，$a$ 取 1~1.5。
  - **强度分（确认）**：用 `concepts/rank` 的 strength/change/speed 做归一（或直接用 rank 档位），给“真强题材”更高权重；热度高但强度差的题材应被明显削弱。
  - **地位分（龙头/前排）**：  
    - 命中主概念且在 `leading`：+X（建议 15~30，且**仅对主概念生效**）  
    - 在 `components`：+Y（建议 5~12）  
    - 同时结合板块“涨停家数/上涨家数”：例如 `limitUpCount>=5` 再额外 +Z（5~10），否则不给。
- **去重与上限**：强烈建议 `Score_concept` 设总上限（比如 40~60），避免题材把排序“拉爆”。

**3) 过滤规则建议（比打分更重要）**
- 增加一个“题材最低门槛”做抗噪：
  - 候选股若**完全不命中**热度 Top20 且 强度榜 TopN（比如 Top30），则不加分甚至降权（不是直接剔除，避免错杀）。
- 增加“题材过热保护”（防追高）：
  - 若板块热度很高但板块涨跌幅 `rise_and_fall` 明显为负，或强度榜靠后：对该概念**不给热度分**，只保留量价主信号。

**4) 验证与回测（避免“看起来更合理”但没收益）**
- **防前视偏差**：`concepts/hot` 是实时口径，回测时要么用“收盘前固定时刻快照”（比如 14:50），要么用“次日开盘前的数据”去做次日交易信号；否则会把盘中信息偷看进来。
- **AB 对比**：同一套交易规则/持有期，仅替换排序方式（原版 vs 加入概念分），看：
  - TopN 命中率（次日/3日上涨概率）、平均收益、最大回撤、换手率
  - 分市场状态（强/弱市）分桶：弱市更依赖题材共振，强市差异可能不大。

**5) 工程落地注意点（你文档里提到的“leading code 格式”很关键）**
- `concepts/detail` 里 `leading` 可能出现 `id: "17:603601"` 或单独 `code`，建议统一做一次“6位代码规范化”再比较。
- 概念接口是外部站点，建议默认**缓存**：
  - `concepts/hot`：缓存 1~3 分钟
  - `concepts/rank`：按日期缓存一天
  - `concepts/detail`：按股票缓存 1 天（或交易日内 30~60 分钟）
- 深度扫描只对“初筛TopX”做是对的；另外建议并发控制（比如 5~10 并发）+ 超时降级（失败就不给概念分，不要影响主流程）。
