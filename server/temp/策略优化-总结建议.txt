
# Volume-Surge 策略优化方案

## 📊 现状分析

### 当前策略架构

**Volume-Surge（强势资金突破）策略** 目前的选股逻辑：

| 维度 | 条件 | 权重 |
|------|------|------|
| 涨幅 | >7%，站上10日均线 | 基础评分 20分 |
| 量能 | 成交额前200，量比/换手率 | 基础评分 35分 |
| K线形态 | 上影线<5%、下影线、振幅 | 基础评分 30分 |
| 市场环境 | 情绪评分、涨停家数、大盘趋势 | 加分 -20~+15分 |
| 首板/连板 | 涨停属性识别 | 加分 0~+15分 |

**问题**：缺乏**板块维度**的考量。同样评分的股票，一个处于热门板块龙头，一个处于冷门板块，前者的成功率明显更高。

---

## 🎯 优化目标

引入概念板块数据，实现：

1. **热点共振加分**：个股所属概念板块越强，加分越多
2. **龙头识别**：同一概念板块内，优先选择涨幅最大/最早启动的个股
3. **板块情绪过滤**：避开当日表现弱势的板块个股

---

## 🚀 优化方案

### 方案一：概念板块强度加分（推荐优先实现）

**原理**：个股所属概念板块在当日排名越靠前，说明资金关注度越高，后续溢价概率越大。

**实现思路**：

```
概念板块加分 = f(板块排名, 板块强度, 是否最相关概念)
```

| 板块排名 | 加分 |
|---------|------|
| Top 3 | +15分 |
| Top 5 | +12分 |
| Top 10 | +8分 |
| Top 20 | +5分 |
| 20名以后 | +0分 |

**特别加成**：
- 如果个股的**最相关概念**（`mostRelevant: true`）在 Top 5 → 额外 +5分
- 个股属于**多个热门板块**（>=2个 Top20 板块）→ 额外 +3分

### 方案二：板块龙头识别

**原理**：同一热门板块内，优先选择龙头股。

**识别规则**：
1. 在当日 Top 10 概念板块中
2. 该板块内涨幅第一或涨停最早
3. 成交额在板块内排名前3

**加分**：
- 板块龙头候选 → +10分
- 板块跟风股 → +0分

### 方案三：板块弱势过滤（风险控制）

**原理**：即使个股表现强势，如果所属板块整体弱势，后续走势可能受拖累。

**过滤规则**：
- 如果个股**最相关概念板块**当日涨幅<0%（绿盘） → 标记为"板块弱势警告"
- 如果所有所属概念板块平均涨幅<0.5% → 扣分 -5分

## 📐 评分体系调整

### 新增：概念板块评分模块

```
概念板块得分 (0 ~ +25分)
├── 热门板块加分: 0 ~ +15分 (根据最强板块排名)
├── 最相关概念加分: 0 ~ +5分 (mostRelevant 在 Top5)
└── 多板块共振加分: 0 ~ +5分 (>=2个 Top20 板块)
```

### 调整后的总评分结构

| 模块 | 分值范围 | 说明 |
|------|---------|------|
| 基础评分 | 0-100分 | 保持不变 |
| 市场环境 | -20~+15分 | 保持不变 |
| 首板/连板 | 0~+15分 | 保持不变 |
| **概念板块** | **0~+25分** | **新增** |
| **最高得分** | **155分** | 原130分 → 155分 |

### 新增风险标记

```typescript
interface VolumeSurge {
  // ... 现有字段
  
  // 新增概念板块相关字段
  conceptBonus: number;           // 概念板块加分
  topConcept: string;             // 最强概念板块名称
  topConceptRank: number;         // 最强概念板块排名
  topConceptStrength: number;     // 最强概念板块强度
  conceptCount: number;           // 所属热门板块数量
  isConceptLeader: boolean;       // 是否板块龙头候选
  weakConceptWarning: boolean;    // 板块弱势警告
}
```

## 🔧 技术实现要点

### 1. 数据获取流程

```
scanAndSave() 执行流程：
1. 获取市场情绪数据（现有）
2. 获取涨停信息（现有）
3. 🆕 获取当日概念板块排行（调用 conceptRankingService）
4. 获取问财选股数据（现有）
5. 🆕 遍历每只股票，获取其所属概念（调用 stockConceptService）
6. 计算评分（新增概念板块加分逻辑）
7. 保存数据
```

### 2. 性能优化建议

由于需要为每只股票调用 `stockConceptService.fetchConcepts()`，建议：

1. **批量获取**：先收集所有股票代码，一次性查询（如果API支持）
2. **缓存机制**：概念板块排行当日只需查询一次，缓存结果
3. **延迟处理**：概念板块加分可以异步计算，不阻塞主流程
4. **限流控制**：添加请求间隔，避免触发API限制

### 3. 数据库Schema更新

需要在 `VolumeSurge` model 中新增字段。
