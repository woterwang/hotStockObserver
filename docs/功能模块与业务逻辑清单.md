# 热搜股票观察系统 —— 功能模块与业务逻辑清单

> 基于当前源码（client/ + server/）梳理，用于快速理解系统整体结构、各模块职责、核心策略口径与数据流。
> 路径均为仓库相对路径。

---

## 0. 系统总览

| 项 | 说明 |
|---|---|
| 定位 | A 股短线复盘与选股辅助平台：热搜/热点追踪 + 多策略选股 + 次日竞价买点信号 + 回测分析 |
| 前端 | React 18 + TypeScript + Vite + TailwindCSS + ECharts（按需注册）+ Axios + React Router 6 |
| 后端 | Node.js + Express + TypeScript + Mongoose(MongoDB) + node-cron + winston + simple-git |
| 部署 | `npm run build` 构建 client 与 server → `server/dist/app.js` 在 production 下直接托管 `client/dist`；PM2 守护（`ecosystem.config.js`），另有 Dockerfile / Nginx 配置 |
| 数据存储 | MongoDB（策略结果、信号、热搜、情绪等）+ 本地 JSON 文件缓存（`server/data/`：K 线、交易日历、情绪、概念热度、回测结果、试盘信号） |
| 外部数据源 | 同花顺（热榜/K线/概念/交易日历/自选分组）、问财 iwencai（条件选股）、开盘啦/龙虎 longhuvip（情绪、板块强度、分时）、腾讯行情 qt.gtimg.cn（实时/竞价）、东方财富 push2（指数/板块/K线） |

### 核心业务主线

```
盘中/盘后数据采集 ──► 多策略选股(候选池, T日收盘后) ──► T+1 集合竞价后打分生成买入信号 ──► 推送同花顺自选分组
        │                           │                                    │
        └──── 市场情绪/交易日历/K线缓存/概念热度 等基础数据支撑 ──────────┘
                                                                         ▼
                                                           历史回测 → 结果落盘 → 前端可视化分析
```

### 1.1 启动流程 — [server/src/app.ts](server/src/app.ts)

### 关键基础规则
- [ ] **热搜落库**：每 15 分钟抓同花顺热榜 Top20 → 补行情 → 计算 `consecutiveDays` → 按 date+stockCode upsert
- [ ] **交易日历**：拉取前 60/后 30 个交易日合并去重；所有“前一交易日/下一交易日”与非交易日跳过均依赖此服务
- [ ] **K 线增量缓存**：`mergeWithoutOverwrite` 仅补缺失日期，避免历史数据被覆盖；盘中缺当日 K 时用腾讯实时行情兜底
- [ ] **市场情绪**：
  - `marketMood.strong`：开盘啦给出的综合强度，被各策略/信号作为环境因子
  - `MarketSentiment.score`：基础 50 分，按涨停数、跌停数、涨跌比、连板高度、炸板率加减，clamp 0-100；≥70 积极 / 55-70 正常 / 40-55 减仓 / <40 暂停

## 4. 选股策略与信号模块（核心业务）

所有策略遵循统一模式：**T 日收盘后扫描候选 → 计算 strategyScore 落库 → T+1 集合竞价后结合开盘数据生成买入信号**。

### 4.1 强势资金突破 / 放量上涨（VolumeSurge）
- 文件：[volumeSurgeServiceV2.ts](server/src/services/volumeSurgeServiceV2.ts)（**生产在用**）；V1 [volumeSurgeService.ts](server/src/services/volumeSurgeService.ts) 仅由 services/index.ts 导出，未被调度/控制器使用
- [ ] 候选来源（问财）：`成交额排名前200` + 量比/换手率/振幅/涨幅/成交量÷前5日均量/所属概念/流通市值，排除 ST/新股/北交所/退市
- [ ] 硬过滤：涨幅 ≥ 7%（量比 <1.5、5日量比 <1.8 仅记录日志不过滤）
- [ ] baseScore 构成：
  - 量比：≥2.5→8，≥2.0→7，≥1.8→6，≥1.5→5
  - 成交量/5日均量：≥2.5→12，≥2.2→10，≥2.0→8
  - 均线位置：close>MA5>MA10>MA20→12；站上三线→10；站上 MA5/MA10 但低于 MA20→6
  - 趋势分：`TrendScorer.calculate`
  - 板块联动 `scoreSectorLink`：个股概念命中热门概念，每命中一个 +10，上限 30
- [ ] marketBonus：涨停数 ≥100 +10 / ≥60 +5 / <30 −10；指数在 MA20 上 +5 否则 −10（V2 中 `indexAboveMa20` 固定为 true）
- [ ] boardBonus：首板 +5，二连板 −10，≥3 连板 −15
- [ ] `strategyScore = clamp(base + marketBonus + boardBonus, 0, 120)`；riskLevel：≥85 且环境好→low，<60 或环境差→high
- [ ] 前端：`/volume-surge`（扫描、按日期/历史汇总、补录历史）

### 4.2 放量上涨交易信号（BuySignal）
- 文件：[buySignalServiceV3.ts](server/src/services/buySignalServiceV3.ts)（**生产在用**：scheduler / buySignalController / newHeightService 均引用 V3；V1/V2 为历史版本）
- [ ] 候选：前一交易日 `VolumeSurge.strategyScore ≥ 50`（可扩展 PriceBreakthrough `turnoverRatio≥1.5`、ConceptResonance `strategyScore≥60`，默认仅 volume_surge）
- [ ] 开盘数据 `getOpeningData`：今日用腾讯实时行情；历史日期用开盘啦分时 09:30 回放；字段含开盘价、开盘涨幅、开盘量比、竞价金额/占比、是否涨停
- [ ] 竞价评分 `getAuctionScore`（满分约 100）：
  - 一票否决：开盘涨幅 < −3% 或 ≥ 7%；低开且竞价量 <3%
  - 竞价涨幅（40）：1~5%→40，5~7%→35，0.3~1%→30，0~0.3%→10
  - 竞价量占比（30）：≥5%→30，3~5%→25，2~3%→15，1~2%→5
  - 量价修正（±30）：高开放量 +30/+15，高开缩量 −30，平开放量 +10/−10，低开放量 −30
- [ ] **totalBuyScore = 板块联动分 + 竞价分×0.3 + 选股分(strategyScore)×0.5 + (marketMood/10)×2**；未命中热门概念板块分扣分
- [ ] 信号分级：≥80 `strong_buy`(仓位30%) / ≥70 `buy`(20%) / ≥50 `hold`(10%) / 其余 `pass`
- [ ] 止损止盈：涨停股 −5%/+15%，其他 −3%/+8%
- [ ] 收益跟踪 `updateProfitTracking`：**仅框架（TODO），未实现**
- [ ] 前端：`/buy-signal`（日期、生成、批量补录、情绪卡片、按信号/策略筛选）

### 4.3 价格突破（PriceBreakthrough）
- 文件：[priceBreakthroughService.ts](server/src/services/priceBreakthroughService.ts)
- [ ] 问财三日条件：Day1 涨幅 >8% 且创 188 日新高；Day2 涨跌幅 ∈(−3%,3%) 且最高价 > Day1 最高价；Day3 开盘价 > Day2 均价、开盘涨幅 ∈(−5%,3%)；排除 ST/新股/北交所/近两年立案
- [ ] 备用单股校验 `checkSingleStock`：涨幅 ≥8% 且最高价突破近 188 日最高
- [ ] 保存：现价、涨幅、成交额、188 日高点、量比 `turnoverRatio`、概念、上涨原因
- [ ] 前端：`/breakthrough`（扫描、按日期/历史汇总）

### 4.4 突破三天交易信号（TradingSignal）
- 文件：[tradingSignalService.ts](server/src/services/tradingSignalService.ts)
- [ ] `generateSignalsForEntryDate(day3)`：Day1=前2交易日、Day2=前1交易日，生成 `breakthrough_3day` 信号（初始 `pending`）
- [ ] 初始出场：止损 = Day2 最低×0.98，止盈 = Day2 收盘×1.10，备选止损 = Day1 收盘
- [ ] `updateSignalsAfterAuction(day3)` 6 项入场条件：开盘>Day2 均价；开盘涨幅 ∈[−5%,5%]；开盘>Day2 最低；Day2 量 ≤ Day1 量×1.1；Day2 收盘在振幅上半区；Day2 上影线 <2%
- [ ] `entryScore` = 满足条件数；6/6→`ready`，≥4→`partial`，否则 `rejected`；止盈改为 Day3 开盘×1.10
- [ ] 状态机：pending → ready/partial/rejected → entered → exited/expired（`markEntry`/`markExit`）
- [ ] `generateVolumeSurgeSignals`：另一套放量信号（成交额前100、涨幅≥8%、换手>5%、非炸板，Day2 震荡确认），按情绪定仓位 0.2/0.3/0.5，止损 −5%/止盈 +12%
- [ ] 前端：`/signals`（生成、更新入场条件、情绪查看、状态筛选）

### 4.5 主线共振（ConceptResonance）
- 文件：[conceptResonanceService.ts](server/src/services/conceptResonanceService.ts)、[types/conceptEnhancement.ts](server/src/types/conceptEnhancement.ts)
- [ ] 量价初筛（问财）：涨幅>7%、成交额前200、上影线<5%、收盘>MA10、排除 ST/新股/北交所/退市/立案
- [ ] baseScore（量价，最高约 100）：涨幅、换手率、上下影线、振幅、成交量/5日均量分档打分
- [ ] 深度扫描：按 baseScore 取前 `deepScanLimit=50`，拉个股概念与热点榜匹配
- [ ] 概念分 `conceptScore`（上限 60）：
  - 热度分 = `21 − 热度排名`（Top20，0~20；概念当日下跌则为 0）
  - 强度分：强度≥80→15，≥60→10，≥40→5，否则热度分减半
  - 地位分：概念龙头 +20 / 成分股 +8；概念涨停数≥5 +5；概念上涨占比>70% +2
- [ ] `strategyScore = clamp(base + marketBonus + boardBonus + conceptScore×β, 0, 160)`，默认 β=0.5（首板 +15、二板 +10、≥3 板 +5）
- [ ] 风险：龙头且概念涨停≥3 → low；热度冷却打 `concept_cooling` 标签
- [ ] 可配置项（`GET/PUT /api/concept-resonance/config`）：beta、hotTopN=20、strengthTopN=30、deepScanLimit=50、concurrencyLimit=5、requestTimeout
- [ ] `getBuySignalList`：取前一交易日 `conceptScore≥30` 候选 + 当日开盘数据 → `ConceptResonanceBuySignals`
- [ ] 回测：默认 conceptScore≥30、总分≥70，开盘买入，止损 5%、止盈 15%、最长持有 3 天，每日最多 3 只，可选只做龙头
- [ ] 前端：`/concept-resonance`（扫描候选 / 买入信号 / 历史回测三 Tab）

### 4.6 百日新高（HundredDayHigh）
- 文件：[newHeightService.ts](server/src/services/newHeightService.ts)（导出名 `hundredDayHighService`）
- [ ] 候选（问财）：涨幅 >8% 且 **收盘价创 188 日新高**，附带概念、流通市值、量比、换手率、振幅；排除 ST/新股/北交所/退市
- [ ] 环境数据：上证是否站上 MA20、当日涨停及连板数（问财）
- [ ] 评分：与强势资金突破 V2 类似（量比、5日量比、均线、上影线、TrendScorer、板块联动）+ marketBonus + boardBonus，上限 120
- [ ] 扫描后将当日候选按分数加入同花顺分组 `{date}-百日新高备选`
- [ ] `generateSignals(date, minScore)`：取 **前一交易日** `HundredDayHigh.strategyScore ≥ minScore` → 调用 BuySignal V3 `generateSignalForStock` → upsert 至 `HundredDayHighSignal`
- [ ] 回测：从 `HundredDayHighSignal` 按 `selectionScore`(默认70) 与 `totalBuyScore`(默认40) 过滤；次日开盘买入，止损 8%、止盈 50%、最长 10 天，每日最多 3 只，仓位按风险系数 1.2/1.0/0.7
- [ ] 前端：`/hundred-day-high`（扫描候选 / 生成信号 / 历史回测、补录）

### 4.7 趋势评分器（TrendScorer）
- 文件：[TrendScorerService.ts](server/src/services/TrendScorerService.ts)
- [ ] 入口自动规范 K 线为“最新在前”，需 ≥20 根
- [ ] 总分 0-100 = 价格趋势(≤40) + 均线趋势(≤35) + 量能趋势(≤25)
  - 价格：5/20 日连续新高次数、高低点抬升、5/10 日涨幅对比滚动分位数
  - 均线：多头排列(含 MA60)、MA5/10/20 斜率分位数、价格站上均线、MA5-MA20 发散度
  - 量能：5日/20日均量比分位数、放量上涨天数、连续放量；量能过弱直接置 0
- [ ] **自适应阈值**：以近 120 日滚动序列计算分位数（Q30/Q60/Q80/Q95，带 fallback）
- [ ] 标签：≥80 VeryStrong / ≥65 Strong / ≥50 Mid / ≥35 Weak / 其余 DownTrend
- [ ] `toBuySignalScore`：原始分 ×0.3 映射为 0-30 买点趋势分

### 4.8 试盘检测（TestPan）
- 文件：[testPanService.ts](server/src/services/testPanService.ts)、[routes/testPanRoutes.ts](server/src/routes/testPanRoutes.ts)

## 6. 定时任务 — [server/src/jobs/scheduler.ts](server/src/jobs/scheduler.ts)

启动时：先更新情绪缓存 `marketMoodService.updateCache/init` → 初始化交易日历 → 注册以下任务。

| 时间 | Cron | 任务 | 内容 |
|---|---|---|---|
| 每日 01:00（工作日） | `0 1 * * 1-5` | autoPush | [autoGit.ts](server/src/jobs/autoGit.ts)：git pull → add → commit → push（同步数据） |
| 05:18（工作日） | `18 5 * * 1-5` | dailyKlineUpdate | [updateCodeKline.ts](server/src/jobs/updateCodeKline.ts)：取前一交易日 VolumeSurge(≥40)/PriceBreakthrough(量比≥1.5)/ConceptResonance(概念分≥30) 股票，批量刷新 K 线缓存 |
| 08:18 每日 | `18 8 * * *` | morningMood | 更新情绪缓存；刷新前一交易日主线共振候选 K 线 |
| 09:26:18（工作日） | `18 26 9 * * 1-5` | auction（竞价后核心任务） | ① BuySignal V3 生成放量信号（选股分≥50），totalBuyScore>40 → 分组 `{日期}-放量大涨`；② 主线共振信号 strategyScore>88 → `{日期}-主线共振`；③ 突破三天信号生成 + 竞价更新，ready → `{日期}-新高T+2`；④ 百日新高信号（≥40，strong_buy/buy）→ `{日期}-放量新高T+1` |
| 9:00-15:59 每 15 分钟（工作日） | `*/15 9-15 * * 1-5` | hotStockUpdate | 刷新同花顺概念热度；交易日抓取热搜 Top20 落库 |
| 15:20 每日 | `20 15 * * *` | tradingCalendar | 更新交易日历缓存 |
| 17:18（工作日） | `18 17 * * 1-5` | afterMarket（串行） | 更新情绪 → 强势资金突破扫描 → 价格突破扫描 → 主线共振扫描 → 百日新高扫描 |
| 23:58 每日 | `58 23 * * *` | dailyConceptUpdate | 落盘概念/行业热度榜 |

> 所有交易相关任务先判断 `tradingCalendarService.isTradingDayByDate`，非交易日跳过。

## 10. 现状与注意事项

- [ ] 多版本服务并存：`volumeSurgeService`(V1) vs `volumeSurgeServiceV2`（在用）；`buySignalService` V1/V2 vs V3（在用）；`services/index.ts` 的统一导出指向旧版本，新增引用需直接 import 在用版本
- [ ] `BuySignal.updateProfitTracking` 未实现，`resultStatus` 基本保持 `pending`
- [ ] 量比、5 日量比、baseScore<70 等阈值在多处仅“日志提示不过滤”，实际以评分排序为主
- [ ] VolumeSurge V2 中 `indexAboveMa20` 硬编码为 true，大盘趋势因子未生效
- [ ] “百日新高”实际口径为 **188 日新高 + 涨幅>8%**（菜单描述“前100交易日新高”与代码不一致）
- [ ] 自选分组推送依赖 `THS_AUTH_COOKIE`；autoGit 每个工作日凌晨自动提交并推送数据，需注意仓库权限与冲突
- [ ] 外部接口（问财 / 同花顺 / 开盘啦 / 东财）均为非官方接口，存在失效、限流（如东财 `ECONNRESET` 时板块数据返回空）风险
- [ ] 试盘(TestPan) 仅有后端 API，无前端页面
